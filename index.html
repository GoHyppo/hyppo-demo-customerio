01 · Identidad

Identificar a la persona

Persona actual: anónima · anonymousId: —

Particularidades
  • identify(id, traits) crea o actualiza el perfil en People. Los traits son atributos del perfil: email, first_name y cualquier otro.
  • Lo que la persona hizo como anónima (con el anonymousId) se asocia al perfil cuando se identifica en el mismo navegador.
  • Si el workspace identifica por email, se puede usar el email como ID; conviene un ID estable de la base del cliente y el email como atributo.
  • reset() borra el usuario y genera un anonymousId nuevo: es el logout.
  • Para encontrarla: People → buscar por ID o email. La actividad está en la pestaña Activity del perfil.

02 · Eventos

Eventos (track)

Particularidades
  • track(nombre, propiedades). Las propiedades se usan en Liquid como {{event.<propiedad>}} dentro de una automation disparada por el evento.
  • Un evento de una persona anónima queda en el anonymousId y se le asigna al perfil cuando se identifica.
  • page() manda un page view. El snippet lo llama solo al cargar; las in-app con page rules lo usan para saber dónde está la persona.
  • Los bloqueadores de anuncios (Brave Shields, uBlock) bloquean cdp.customer.io. En un cliente real, los eventos clave conviene mandarlos también desde el backend por la HTTP API (ver scripts/seed.sh).
  • Para verlos: Data & Integrations → JavaScript → Data In (llegada en vivo) y la Activity del perfil.

03 · Tienda

Carrito y compras

Particularidades
  • Customer.io no tiene una llamada aparte para compras: son eventos. La demo usa los nombres de la spec de ecommerce (Product Added, Order Completed), que reconocen los destinos de Data Pipelines.
  • Order Completed con revenue sirve para medir conversiones de una automation (Conversion goal).
  • Para un carrito abandonado: automation con trigger Product Added y exit condition Order Completed.

04 · In-app messages

Disparar un in-app

Particularidades
  • Primero se habilita in-app en Workspace Settings → In-App. Con eso el snippet carga el plugin solo; con una key pk_ no hace falta el Site ID.
  • Para probar: automation con trigger "Performed event demo_inapp" y un mensaje In-App. Solo llega a personas identificadas (salvo que se active anonymousInApp).
  • Al principio el plugin consulta despacio, cerca de una vez por minuto. Después del primer mensaje pasa a tiempo real.
  • Los eventos del mensaje (abierto, cerrado, acción) aparecen en el log.

05 · Objetos

Empresa (group)

Particularidades
  • group(id, traits) crea un objeto y lo relaciona con la persona identificada. Sirve para modelos B2B (una cuenta con varias personas) o para cursos, vuelos, etc.
  • El tipo de objeto va en traits.object_type_id (por defecto 1, el primero que se creó en Data Index → Objects). Si el workspace no tiene tipos de objeto, el llamado no crea nada.
  • Hay que identificar a la persona antes: sin userId no hay relación.
